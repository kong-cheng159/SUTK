# 游戏内新增官职操作步骤（FModel / 小 pak）

本文给**负责改游戏资源的人**照做。

## 推荐方案：复用库内已有 id（当前采用）

不必新建 `701`。全库约 710 职名里，汉系面板只用 **1–144**；其余 id 在 `DT_Official` / locres **本来就有**。

| 项 | 值 |
|----|-----|
| id | **4091**（库内已有） |
| 游戏原名 | **破虏将军** |
| 修改器 / 游戏职名 | **破虏将军**（与 locres 一致） |
| 等级 | **8 星**（与 DT 中该行一致） |
| 编制（修改器） | **11000** |

`desktop/data/officials_mod.json` 已按此配置。

### 不改游戏时，能不能生效？

| 场景 | 结果 |
|------|------|
| 修改器任命 / 自动任命 / 存档 `info.official=4091` | **可以** |
| 游戏读档后编制/效果 | **可以**（读的是原表 4091 行） |
| 游戏里显示的职名 | **破虏将军**（任命后在武将任职处可见；任免面板仍可能无此行） |
| 游戏「势力→官职」面板是否多一行 | **通常不会**（4091 不在汉系 1–144 列表里）；任职仍可通过修改器写入 |

若只要「有个 8 星职能任命、游戏不崩」，**改修改器即可，不必动 pak**。

### 若还要任免面板多一行（4091）

比新建 701 简单：

1. 把 **4091** 加进汉系任免 id 列表（见下文第 7 节）。  
2. **不必**改 locres、不必往 `DT_Official` 增行（行与名称已存在）。

## 4. FModel 基础设置

1. **Directory → Selector**（或 Settings 里的 **Game's Archive Directory**）指向游戏根（含内层 `ProjectA` 的那一层）：
   ```
   ...\Seres Universalis Three Kingdoms Demo\Seres Universalis Three Kingdoms Demo
   ```
2. 引擎选 **UE5**，加载 `Content\Paks\pakchunk0-Windows.pak`。
3. 确认能搜到：`DT_Official`、`Game.locres`、`BP_OfficePanel`、`DT_FactionRank`。

也可不挂 pak，直接用 FModel **打开本地** `unpack_out` 里已解出的文件。

### 关于「Oodle」——设置里没有这个菜单项

**Oodle 不是 Settings 里的一个选项**，而是解压 pak 用的 **DLL 文件**（文件名：`oo2core_9_win64.dll`）。

FModel 会把它放在 **Output Directory 下的 `.data` 文件夹**里，例如本机当前配置为：

```
D:\Program Files (x86)\Steam\steamapps\common\Seres Universalis Three Kingdoms Demo\
Seres Universalis Three Kingdoms Demo\.data\oo2core_9_win64.dll
```

（Output Directory 在 Settings → **Output Directory**；本机曾设成游戏根目录，所以 `.data` 就在游戏根下。）

**怎么处理：**

1. 若 FModel **已经能打开** `pakchunk0-Windows.pak` 并浏览资源 → **不用管 Oodle**，说明已可用（首次联网启动常会自动下载）。
2. 若报错 `Unable to load oo2core_9_win64.dll` / 打不开 pak：
   - 把仓库里的文件复制到上面的 `.data\`：
     ```
     E:\JZ-ROS\TEST\SUTK修改器_便携版\desktop\tools\oo2core_9_win64.dll
     ```
   - 复制后文件名必须是 **`oo2core_9_win64.dll`**（不要改名）。
   - 重启 FModel 再加载 pak。

仓库里用 `repak.exe` 解包时同样依赖该 DLL（`extract.ps1` 已自动设置 `EPIC_GAMES_OODLE_PATH`），与 FModel 设置菜单无关。

## 6. 改数据表 `DT_Official`（必须有 701 行）

**主文件（成对保存）：**

```
unpack_out\ProjectA\Content\DataTable\Generate\Common\DT_Official.uasset
unpack_out\ProjectA\Content\DataTable\Generate\Common\DT_Official.uexp
```

**操作：**

1. 打开 `DT_Official`（FModel 浏览字段；**增行优先 UAssetGUI** 打开上述 `.uasset`）。
2. 找到行名 **`OfficialName_121`**（强弩将军）。记录：**等级 8、编制 11000、官职效果、以及与汉系面板相关的标志字段**（勿照抄 id 1001+ 其它路线行）。
3. **复制该行**，新行名改为 **`OfficialName_701`**。
4. 确认：
   - 等级 = **8**
   - 编制 = **11000**
   - 效果：可先与 121 相同，再按策划改
5. 保存后行数应为 **711**（原 710 + 1）。**`.uasset` 与 `.uexp` 必须一起更新。**

`DataTableModify\...\DT_Official` 体积很小，可先不动；若进游戏异常再对照主表处理。

**验收（可选）：** 用十六进制/脚本在 `.uexp` 中应能搜到字符串 `OfficialName_701`。

## 7. 任免面板列表加入 701（否则游戏里仍只有 144 行）

汉系「势力 → 官职」不是自动显示表内全部官职，而是 **绑定的 id 列表（约 1–144）**。

1. 在 FModel 中对 **`OfficialName_121`** / **`121`** 查引用（References / Find usages）。
2. 重点检查：
   - `ProjectA/Content/DataTable/Generate/Common/DT_FactionRank`（搜 **`han8`** 等汉系爵位）
   - `ProjectA/Content/UI/Game/Faction/BP_OfficePanel`
3. 找到与 **121、122、129** 同级的 **官职 id 数组 / 列表**，在合适位置（建议 8 星段、靠近 121）**追加 `701`**。
4. 把改过的 `.uasset` / `.uexp` 按**相同相对路径**放进 `unpack_out`。

若只完成第 5、6 步、漏做本步：修改器能任命 701，**游戏面板仍看不到伏波将军**。

## 12. 常见问题

| 现象 | 可能原因 |
|------|----------|
| 游戏闪退 / 进不了官职页 | `DT_Official` 只改了 uexp 或行结构错误；删小 pak 回滚后重做 |
| 有任职但面板无此行 | 漏做第 7 节列表绑定 |
| 有行但名称为空/乱码 | locres 未加键，或小 pak 里 locres 不是改完的那份 |
| 修改器有、游戏没有 | 只写了 JSON，未装有效 mod pak |
| FModel 能看表不能增行 | 用 UAssetGUI 改 `unpack_out` 里的 `DT_Official.uasset` |
| UAssetGUI 打不开 / 保存后崩 | UE 映射不匹配；换版本或换工具，勿强行覆盖 |

## 13. 再新增其它官职时

1. 选 **未占用 id**（见 [官职列表.md](官职列表.md)；701 已被伏波占用则换新号）。  
2. 复制 **同星级** 汉系面板行（如 8 星用 121，9 星用 144）。  
3. 同步：`OfficialName_<id>` + `DT_Official` 行 + 面板列表 + `officials_mod.json` + `pack.ps1`。

编制默认：`(等级+3)×1000`。俸禄展示：`等级×2+2`。
